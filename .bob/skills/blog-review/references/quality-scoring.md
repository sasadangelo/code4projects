# Blog Quality Scoring Checklist — Code4Projects

Score each blog post against this checklist at the end of every review.
Deduct points for each failed check and append all gap items to the issue list.

---

## Content Quality (30 points)

| Check | Points | Pass Criteria |
|---|---|---|
| Coverage / comprehensiveness | 7 | Covers the reader task with useful subtopics and concrete code examples; no raw word-count target |
| Readability | 7 | Prose matches a developer audience; default Flesch 60–70, 55–75 acceptable; dense technical explanations are fine when necessary |
| Originality / unique value | 5 | Working code, real terminal output, original diagrams, or first-hand project experience; theory without practice earns nothing |
| Sentence & paragraph structure | 4 | Clear, coherent pacing; no fixed sentence, paragraph, or heading quota |
| Engagement elements | 4 | "You should read this if:" list in Introduction, summary bullets in Conclusion, callout blocks where useful |
| Grammar / clarity | 3 | Clean prose, controlled passive voice, no forbidden words (`basically`, `simply`, `just`, `obviously`, `leverage`, `synergy`) |

---

## SEO Optimization (25 points)

| Check | Points | Pass Criteria |
|---|---|---|
| Heading hierarchy and purpose fit | 5 | H1 (post title) → H2 (sections) → H3 (sub-sections), no skipped levels; headings describe the reader task |
| Title clarity and purpose fit | 4 | Accurate, distinctive title in Title Case, consistent with visible content |
| Semantic topic consistency | 4 | Title, headings, and body describe the same reader task |
| Internal linking (3–10 contextual) | 4 | Descriptive anchor text, bidirectional where relevant, uses `{{ site.baseurl }}/slug/` format |
| URL / slug structure | 3 | Kebab-case, no trailing slash, stable and readable |
| Meta description (`excerpt:`) | 3 | 1–2 sentences, ≤ 160 chars, no markdown, useful page-specific summary |
| External linking (tier 1–3) | 2 | 3–8 outbound links to authoritative sources (official docs, papers, major tech publications) |

---

## E-E-A-T Signals (15 points)

| Check | Points | Pass Criteria |
|---|---|---|
| Author attribution | 4 | `author:` field in front matter present; bio page exists |
| Source fidelity | 4 | Material claims are traceable; no fabricated statistics |
| Trust indicators | 4 | Site has contact page, about page, editorial policy — site-level check, counts for every post |
| Evidence basis | 3 | Working code and real output are the primary evidence; external sources cited where claims go beyond the author's direct experience |

---

## Technical Elements (15 points)

| Check | Points | Pass Criteria |
|---|---|---|
| Schema markup baseline | 4 | `Article`/`BlogPosting` + `Person` + `Organization` + `BreadcrumbList` present in the Jekyll theme |
| Image optimization | 3 | AVIF/WebP preferred, descriptive alt text on all images, `loading="lazy"` on all except the hero (LCP) |
| Structured data elements | 2 | Tables with `<thead>`, numbered lists, comparison blocks where content warrants them |
| Page speed signals | 2 | Hero image has `fetchpriority="high"` or `{:width="760" height="400" .responsive_img}`; no render-blocking scripts added by the post |
| Mobile-friendliness | 2 | Responsive images, code blocks do not overflow, no horizontal scroll introduced by the post |
| OG / social meta tags | 2 | `image:` (og:image) present in front matter; `og:title` and `og:description` generated by theme |

---

## AI Citation Readiness (15 points)

| Check | Points | Pass Criteria |
|---|---|---|
| Evidence-backed citability | 4 | Key technical claims are self-contained and supported by working examples or cited sources |
| Purpose fit and reader utility | 3 | Clear page purpose; headings describe the reader task and match the post intent |
| Entity clarity | 3 | Unambiguous topic entity, consistent terminology throughout (e.g. always "Docker", never alternating "Docker" / "container engine") |
| Content structure for extraction | 3 | Answer-first sentences in key sections, tables with `<thead>`, comparison formats where appropriate |
| AI crawler accessibility | 2 | No `robots.txt` rule blocks Googlebot or declared AI crawlers; primary content in initial HTML |

## Total: 100 points

## Scoring Bands

| Score | Rating | Action |
|---|---|---|
| 90–100 | **Exceptional** | Publish as-is; flagship content |
| 80–89 | **Strong** | Minor polish; ready for publication |
| 70–79 | **Acceptable** | Targeted improvements needed before publish |
| 60–69 | **Below Standard** | Significant rework required |
| < 60 | **Rewrite** | Fundamental issues; start from outline |

## Priority Classification

Use these priorities when appending gap items to the issue list.

### 🔴 Critical (must fix before publishing)

- Fabricated statistics (zero tolerance)
- Broken heading hierarchy (e.g. H2 → H4 skip)
- No source attribution on material claims
- Missing `author:` field in front matter
- Primary content inaccessible to crawlers (robots block, auth wall, render failure)

### 🟡 High Priority

- Important sections obscure their conclusion or lack supporting code/evidence
- Missing `Article`/`Person`/`Organization`/`BreadcrumbList` schema baseline
- Missing `excerpt:` (meta description)
- No internal links
- Flesch score outside 55–75 range
- No OG image (`image:` missing from front matter)
- `loading="lazy"` on hero image (LCP regression)
- Passive voice dominant (> 15 % of sentences)
- Fewer than 3 external links to tier-1 sources

### 🟠 Medium Priority

- Fewer than 2 diagrams or images beyond the hero
- Inconsistent entity terminology
- Self-promotion > 1 mention per post
- Sections exceeding 300 words without a sub-heading
- Unsupported first-hand experience claims (no code output, no methodology)
- Images not in AVIF/WebP format
- Average sentence length > 22 words

### 🔵 Low Priority

- Missing alt text on non-hero images
- Minor terminology inconsistency
- Transition word density outside 15–35 %
- Charts lack type diversity

## Quick Automated Checks

These signals can be detected programmatically from the Markdown source.

### Content Quality

- Flesch-Kincaid score (target 60–70, acceptable 55–75)
- Paragraph density — flag paragraphs > 5 sentences (descriptive; escalate only if comprehension is affected)
- Average sentence length (descriptive; flag > 22 words)
- Passive voice sample (flag > 15 %)
- Forbidden words: `basically`, `simply`, `just`, `obviously`, `leverage`, `synergy`
- `## Introduction` and `## Conclusion` present

### SEO Optimization

- Heading hierarchy: `^#{1,6}` regex — no skipped levels
- `excerpt:` present and ≤ 160 chars
- Internal link count (relative URLs or same-domain)
- External link count and rough tier classification
- `slug:` kebab-case, no trailing slash

### E-E-A-T Signals

- `author:` field in front matter
- Unsourced statistics: numbers without nearby attribution
- Fabricated or unverifiable statistics

### Technical Elements

- Image count: `regex !\[` or `<img`
- Alt text presence: images without alt attribute
- `image:` present in front matter (OG image)
- `loading="lazy"` on first image (flag as LCP issue)
- `{:width="760" height="400" .responsive_img}` on hero image

### AI Citation Readiness

- Table presence with `<thead>`
- `robots.txt` does not block major crawlers (site-level check)
- Primary content rendered in initial HTML (no JS-only rendering introduced by the post)
