Learn <b>software architecture</b> the way it is practised on real projects: as a set of decisions driven by requirements. This category starts from the inputs — <b>lean requirements</b>, personas, scenarios, and a <b>domain model</b> derived from them — and moves to the patterns that turn those decisions into code: <b>layered</b>, <b>hexagonal</b>, <b>clean</b>, and <b>event-driven</b> architectures, and the pragmatic hybrids that real systems end up with. Every article uses working Python projects such as FastURL, so you can see how each pattern shapes folders, dependencies, and tests rather than only diagrams.
